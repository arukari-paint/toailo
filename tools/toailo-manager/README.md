# TOAILO Manager

TOAILO 公式サイトに AI活用ガイドの記事を追加するための、Mac 上で動くローカル管理ツールです。

- ChatGPT 用の指示文を作る → ChatGPT で記事を書く（手動）→ 取り込む → プレビュー → 承認 → Pull Request → マージで公開
- 127.0.0.1 でだけ動きます。外部のサーバー・データベース・AI API は使いません（追加の費用はかかりません）
- 公開サイトのビルド（`dist/`）には含まれません

## 起動と停止

**起動**：Finder で `tools/toailo-manager/TOAILO Manager.command` をダブルクリックします。

- ターミナルが開き、Node.js 24 以上・git・GitHub CLI（gh）を確認してから、ブラウザで管理画面が開きます
- 初回だけ「開発元を確認できないため開けません」と出た場合は、ファイルを右クリック →「開く」を選んでください
- ポートは 4870 から空いている番号を使います。すでに起動している場合は、その画面を開くだけです
- ターミナルから起動する場合：`npm run manager`

**停止**：管理画面右上の「停止」ボタン、またはターミナルのウィンドウで `Ctrl + C`。

### 事前に必要なもの

| もの | 確認・準備 |
|---|---|
| Node.js 24 LTS | `node -v`（Homebrew：`brew install node@24`） |
| GitHub CLI | `gh auth status`（ログインしていなければ `gh auth login`）。公開（PR作成）だけに使います |
| 依存パッケージ | 初回起動時に自動で `npm ci` します |

GitHub の認証情報はこのツールでは保存しません（`gh` のログイン情報をそのまま使います）。

## 月1回の運用手順

1. **起動**して、ダッシュボードで「GitHubと同期」を押す（前回の PR の公開状況が反映されます）
2. **今月の記事を作成**：本数（基本2本・最大4本）を選んで「指示文を作成」→「指示文をコピー」
3. ChatGPT の新しいチャットに貼り付けて送信し、出力された記事（```markdown のブロック）をまとめてコピー
4. **記事を取り込む**：貼り付けて「検証して取り込む」。エラーのある記事は取り込まれません（理由が表示されます）。直す場合は ChatGPT に修正を頼むか、テキストを直して取り込み直します
5. **記事一覧** → 記事を開いてプレビュー（PC幅・スマホ幅）を確認し、「確認待ちにする」→ 内容に問題なければ「承認する」
   - 本文の事実関係（アプリの機能・料金）、外部情報の出典、サンプルデータの表記を確認してください
6. **公開**：承認済みの記事を選んで「選んだ記事で Pull Request を作成」
   - 自動で：作業ツリーの確認 → 専用ブランチ（`articles/日付-xxxxx`）作成 → 記事ファイル追加（公開日を当日に設定）→ 型チェック → ビルド → 内部リンク検証 → 記事ファイルだけをコミット → push → PR 作成
7. GitHub で PR を開いて内容を確認し、**マージ**（ここで初めて main に入り、GitHub Actions が公開します）
8. 数分後、管理画面で「GitHubと同期」→ デプロイ成功を確認できた記事が「公開済み」になります

月2本は目安です。品質に納得できない記事を、本数のために公開する必要はありません。

## 記事の状態

| 状態 | 意味 | 次にできること |
|---|---|---|
| 下書き（draft） | 取り込んだ直後 | 確認待ちにする／却下／削除 |
| 確認待ち（review） | 人の確認を待っている | 承認（確認ダイアログあり）／下書きに戻す／却下 |
| 承認済み（approved） | 人が承認した。公開できる | PR を作成／承認の取り消し |
| 公開済み（published） | PR がマージされ、デプロイ成功を確認した | （同期処理だけが設定） |
| 却下（rejected） | 公開しない | 下書きに戻す／削除 |

PR の段階は記事の状態とは別に「公開」画面で管理します：処理中 → PR作成済み・マージ待ち → マージ済み・デプロイ確認待ち → 公開済み（または 失敗／PRクローズ）。

- 承認済みの記事しか PR にできません。原稿を取り込み直すと承認は取り消され、下書きに戻ります
- `main` へ直接 push することはありません

## 失敗したとき

- 処理の各ステップの結果は「公開」画面の「処理の記録」に残ります
- **コミット前の失敗**（型チェック・ビルド・リンク検証など）：追加した記事ファイルとブランチを片付けて元のブランチに戻ります。「再試行（最初から）」で最初からやり直します
- **push・PR 作成の失敗**（ネットワークなど）：コミット済みのブランチを残します。「再試行（push から続ける）」で続きから実行します
- 処理中にツールが終了した場合は、次回起動時に「失敗」として扱い、再試行できます
- 「サイトのフォルダに未コミットの変更があります」と出たら、`~/Projects/toailo-site` の変更をコミットするか元に戻してから公開してください（記事以外の変更が PR に混ざらないようにするため）

## データの保存場所

`tools/toailo-manager/data/`（Git 管理外。`.gitignore` 済み）

| ファイル | 内容 |
|---|---|
| `state.json` | 記事の状態・履歴、公開バッチ（PR・デプロイの結果）、最終同期・最終指示文作成の日時 |
| `articles/<slug>.md` | 取り込んだ記事の原稿 |
| `prompt-template.md` | 「共通指示文」で編集した場合だけ作られる（標準は `tools/toailo-manager/prompt-template.md`） |

個人情報・API キーは保存しません。公開済みの記事は、常に GitHub（`origin/main`）の `src/content/guides/` を正として数えます。

## 仕組み（開発者向け）

| ファイル | 役割 |
|---|---|
| `server.mjs` | 起動（127.0.0.1・空きポート・ブラウザを開く・停止） |
| `lib/app.mjs` | API・静的ファイル。Host ヘッダーの確認、変更系は専用ヘッダー必須 |
| `lib/site-loader.mjs` | サイトの `src/data/apps.ts`・`src/content.config.ts` などを Node.js から直接読み込む（サイト側は変更しない） |
| `lib/validate.mjs` | 取り込み時の検証（スキーマは `content.config.ts` の zod をそのまま使用） |
| `lib/prompt.mjs` | 指示文の生成（`prompt-template.md` に最新のサイト情報を差し込む） |
| `lib/preview.mjs` | プレビュー（Astro 7 と同じ Markdown 処理系・サイトの CSS。sandbox iframe + CSP でスクリプト無効） |
| `lib/publish.mjs` | ブランチ作成〜PR 作成。各ステップを記録し、途中から再試行できる |
| `lib/sync.mjs` | PR の状態・マージ・GitHub Actions（deploy.yml）の結果を確認 |
| `test/` | `npm run test:manager`（GitHub には接続しません。公開フローは一時的なローカル Git リポジトリで検証） |
